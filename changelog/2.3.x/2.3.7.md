# 2.3.7 — 2026-10-14

## Added

- **`ntfy_fetch_messages` takes `cursor` and returns `nextCursor` and `totalCount`**, paging a window larger than one call returns oldest-first; a duration `since` keeps its window start in the cursor. An unknown cursor fails with the new `cursor_not_found` reason ([#27](https://github.com/cyanheads/ntfy-mcp-server/issues/27)).
- **`upstreamTruncated` on `ntfy_fetch_messages` and the `ntfy://{topic}` resource** is set when ntfy capped the replay (`X-Messages-Truncated`) and dropped the oldest messages; a notice says so ([#36](https://github.com/cyanheads/ntfy-mcp-server/issues/36)).
- **`markdown: true` on fetched and published messages** ntfy marked `text/markdown`; the body is fenced as `markdown` in `content[]` ([#28](https://github.com/cyanheads/ntfy-mcp-server/issues/28)).
- **`NTFY_ENABLE_EMOJI_TAGS`** (default `true`); `false` removes `ntfy_search_emoji_tags` from `tools/list` and drops the server instructions' and `ntfy_publish_message`'s pointers at it. `./.env` is read before the tools register ([#32](https://github.com/cyanheads/ntfy-mcp-server/issues/32)).
- **`invalid_delay` on `ntfy_publish_message`** for ntfy's three `delay` rejections (40004, 40005, 40006), with a recovery hint ([#29](https://github.com/cyanheads/ntfy-mcp-server/issues/29)).
- **`rate_limited` on `ntfy_fetch_messages`, `ntfy_manage_message`, and `ntfy://{topic}`**, carrying `retryAfter` when ntfy sent one; `ntfy_publish_message` now carries `retryAfter` too ([#38](https://github.com/cyanheads/ntfy-mcp-server/issues/38)).
- **`upstream_malformed`** on `ntfy_fetch_messages`, `ntfy://{topic}`, `ntfy_publish_message`, and `ntfy_manage_message` ([#24](https://github.com/cyanheads/ntfy-mcp-server/issues/24), [#39](https://github.com/cyanheads/ntfy-mcp-server/issues/39)).

## Changed

- **`ntfy_manage_message` no longer advertises `idempotentHint`**: every clear or delete appends a new event ([#25](https://github.com/cyanheads/ntfy-mcp-server/issues/25)).
- **`limit` above the per-call cap is served at the cap with a notice**: `ntfy_fetch_messages` 101–1000 returns 100, `ntfy_search_emoji_tags` 201–1000 returns 200. Both were rejected.
- **`NTFY_REQUEST_TIMEOUT_MS` is per attempt and covers the response body**, and one 50 s deadline bounds all attempts and backoff. A stalled or hung upstream used to run 63–64 s or never settle; caller cancellation now aborts a body read ([#37](https://github.com/cyanheads/ntfy-mcp-server/issues/37)).
- **The `ntfy://{topic}` resource fails at the call deadline with `-32000` `upstream_unreachable`**, where it failed `-32004` ([#37](https://github.com/cyanheads/ntfy-mcp-server/issues/37)).
- **`ntfy_publish_message`'s `delay` description** gives "10s minimum; maximum 3 days by default (configurable per ntfy server)"; the `since` description and `invalid_since` hint list duration units `s`, `m`, `h` only.
- **`.mcpbignore` keeps `src/`, `tests/`, `scripts/`, `docs/`, `.github/`, `.vscode/`, and `coverage/` out of the `.mcpb` bundle**; the Docker image uses Bun 1.4.3 and a bun-native `HEALTHCHECK` on `/healthz`.

## Fixed

- **A blank or whitespace-only `since` on `ntfy_fetch_messages` meant `all`** and now means the `10m` default, which the response echoes. Whitespace-only `id`, `title`, `message`, and `tags` entries are no longer treated as filters; a blank `id` no longer lifts the body cap ([#26](https://github.com/cyanheads/ntfy-mcp-server/issues/26)).
- **A poll body with an unparseable line, or a `200` that is not ntfy's message stream, was returned as a short or empty topic.** It is retried, then fails `upstream_malformed` ([#24](https://github.com/cyanheads/ntfy-mcp-server/issues/24)).
- **An ntfy error line inside a `200` replay surfaced as `Invalid Date`** and now maps to the error it carries, such as `rate_limited` ([#24](https://github.com/cyanheads/ntfy-mcp-server/issues/24), [#38](https://github.com/cyanheads/ntfy-mcp-server/issues/38)).
- **A `200` reply to a publish or clear/delete that is not an ntfy message surfaced as an internal error** and now fails `upstream_malformed`, without a resend ([#39](https://github.com/cyanheads/ntfy-mcp-server/issues/39)).
- **ntfy's 40006 (`delay` too far out) mapped to `payload_too_large`** and now maps to `invalid_delay` ([#29](https://github.com/cyanheads/ntfy-mcp-server/issues/29)).
- **`payload_too_large` for an oversize `title` (40057) or `tags` (40058) told the caller to shorten the message body**; the hint now names the field ([#35](https://github.com/cyanheads/ntfy-mcp-server/issues/35)).
- **Paging advice was unreachable**: passing a returned `id` as `since` never reached the dropped messages; the tool text now points at `cursor` ([#27](https://github.com/cyanheads/ntfy-mcp-server/issues/27)).
- **ntfy-supplied values rendered as Markdown in `content[]` and in consent prompts**; they now render as literal text, so an actions button no longer swallows the messages after it ([#28](https://github.com/cyanheads/ntfy-mcp-server/issues/28)).
