# 2.3.6 — 2026-10-07

## Changed

- **`server.json` npm entries launch via `npx` without `run start:*` arguments, and the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `http`** (mcp-ts-core 0.13.11, cyanheads/mcp-ts-core#622).
- **Tool error results end with `request <id>` and carry `data.requestId`** (mcp-ts-core 0.13.10, cyanheads/mcp-ts-core#576).
- **A declared `recovery` hint reaches the client without `ctx.recoveryFor`**, so the forwards in all three tools' `ctx.fail` calls are dropped; no client-visible change from the drop itself (mcp-ts-core 0.13.10, cyanheads/mcp-ts-core#579).
- **`ctx.inputs` keeps only responses the client's declared capabilities cover** (mcp-ts-core 0.13.10, cyanheads/mcp-ts-core#496).
- **Argument-rejection hints name the field path, and an integer sent for a string field is accepted as its digits** (mcp-ts-core 0.13.9, cyanheads/mcp-ts-core#493, cyanheads/mcp-ts-core#487).
- **`ctx.log` notifications to the client honor `MCP_LOG_LEVEL` and mask sensitive fields** (mcp-ts-core 0.13.11, cyanheads/mcp-ts-core#621, cyanheads/mcp-ts-core#630).
- **MCP SDK `@modelcontextprotocol/server` 2.0.0 → 2.2.0** (mcp-ts-core 0.13.9, 0.13.11): a 2026-07-28 POST without `MCP-Protocol-Version` is refused `400`, and a JSON-RPC batch over 100 messages is refused.
- **Docker image installs production dependencies in a `$BUILDPLATFORM` `deps` stage**, so Bun no longer runs under QEMU in multi-arch builds (mcp-ts-core 0.13.10), and drops musl-only bindings (0.13.11); Bun 1.4.0 → 1.4.2, and the image carries an `org.opencontainers.image.version` label.
- Docs: `MCP_REQUEST_STATE_KEY` and `STORAGE_PROVIDER_TYPE` are documented for HTTP deployments in `.env.example` and the README (`MCP_REQUEST_STATE_KEY` also in `server.json`); `.env.example` also lists `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `LOG_LLM_INTERACTIONS`, and the OTLP traces, metrics, and logs endpoint variables.
- Framework skills and scripts are synced to the 0.13.13 template; `.gitignore` and `.dockerignore` cover every `.env*` file (`.dockerignore` also the MCP registry token files), `.mcpbignore` excludes `/docs/idea.md`, `/logs/`, and `/.cache/`, the npm package leaves out `dist/*.mcpb`, and CodeQL runs one job per language.

## Security

- **The consent gate on `ntfy_manage_message` and on `ntfy_publish_message` publishes carrying `email`, `call`, or a `broadcast`/`http` action acts only on an answer to a prompt the server recorded.** Each prompt stores a single-use record in `ctx.state` (operation, authenticated caller, target, SHA-256 of the exact outbound request) and sends its id as `requestState`; every call redeems the record first. A pre-answered, replayed, fabricated, or mismatched confirmation re-asks and sends nothing upstream, where before an accepted answer in `ctx.inputs` alone was acted on. Redeeming refuses sequential replays; retries carrying one id at the same moment can each proceed until `ctx.state` offers an atomic read-and-delete (cyanheads/mcp-ts-core#593). Multi-instance HTTP deployments need shared `STORAGE_PROVIDER_TYPE` storage, and should set `MCP_REQUEST_STATE_KEY`; under `MCP_AUTH_MODE=jwt` or `oauth`, a gated call needs a token carrying a `tid` claim, since the record lives in tenant-scoped storage. `tools/list` is unchanged.
- **Error data sent to clients no longer carries server stack traces** (mcp-ts-core 0.13.7, cyanheads/mcp-ts-core#519), **request context or elicited answers** (0.13.8, cyanheads/mcp-ts-core#548), **or `data.rootCause`** (0.13.13, cyanheads/mcp-ts-core#644).
