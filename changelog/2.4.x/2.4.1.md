# 2.4.1 — 2026-11-14

## Added

- **`ntfy_publish_message` `timezone` input**: an IANA zone name in which ntfy reads a natural-language `delay` (`tomorrow, 10am`); a blank value is treated as unset, and a name ntfy rejects (40059) fails as the new `invalid_timezone` reason. `delay` also takes an RFC 3339 time with its `Z` or `±hh:mm` offset ([#50](https://github.com/cyanheads/ntfy-mcp-server/issues/50)).
- **`ntfy_fetch_messages` marks a row still queued for delivery with `scheduled: true`** and renders its timestamp as `Delivers:`, when the call sets `scheduled: true` and the row's `time` is later than ntfy's clock (the response's `Date` header, or this server's clock when it is missing). `time` is documented as the accept time of an immediate publish or the delivery time of a delayed one ([#51](https://github.com/cyanheads/ntfy-mcp-server/issues/51)).
- **`ntfy_search_emoji_tags` `query` accepts `:code:`, spaced or hyphenated names, and one emoji** (`:warning:`, `heavy check`, `⚠️`, with or without a skin tone); `effectiveQuery` echoes the normalized query, and a query that normalizes to nothing lists the reference ([#53](https://github.com/cyanheads/ntfy-mcp-server/issues/53)).
- **`encoding` on fetched rows and `ntfy://{topic}` rows** (`base64` when ntfy stored a body that was not UTF-8 text), and **`id` on their action buttons**.
- **`NTFY_CLAMP_LIMITS`** (default `true`) and the `ntfy.limit.clamps` counter: each clamped `limit` logs `Clamped limit` at `info` and increments the counter.

## Changed

- **A `limit` above the per-call cap is served as the cap** (100 for `ntfy_fetch_messages`, 200 for `ntfy_search_emoji_tags`) with a notice, and the schema advertises no maximum. 2.4.0 advertised `maximum: 1000` and rejected a larger value; `NTFY_CLAMP_LIMITS=false` advertises and enforces a maximum equal to the cap.
- **An empty `ntfy_fetch_messages` result under `since: all` says that window is everything ntfy still caches** instead of suggesting a wider one, and without `scheduled: true` it notes that a delayed message not yet delivered is returned only with it.
- **`ntfy_publish_message` descriptions follow ntfy's current docs**: `markdown` renders in the web app and the Android app, and `email: "yes"` uses the primary verified address.
- **`ntfy-guide` skill 1.0 → 1.1**: reminders cover `timezone` and RFC 3339 times, queued rows, `icon` in updates, the reserved topics `docs`, `static`, and `file`, and a numeric `since` in seconds.
- **Bun floor rises to `>=1.4.4`** (`engines.bun`, README) with mcp-ts-core 0.13.22.
- **A failure that carries `retryAfter`** (`rate_limited`, `upstream_unreachable`) ends its `content[]` text with `retry after <value>` in the trailer (mcp-ts-core 0.13.19).
- **A failed `ntfy://{topic}` read writes an error log record** (mcp-ts-core 0.13.20).
- **An upstream failure that bubbles unclassified no longer carries `body` or `responseBody` in its error data to the client**; the captured body stays in server logs (mcp-ts-core 0.13.22).
- **`.env.example` lists `MCP_JWT_EXPECTED_AUDIENCE` and `MCP_JWT_EXPECTED_ISSUER`**; JWT mode warns at startup when no audience is set (mcp-ts-core 0.13.20).

## Fixed

- **`ntfy_publish_message` with `filename` and no `attach`, answered by ntfy with HTTP 500 code `50001`, fails as `invalid_attachment` after one request** with a hint to pass the file's URL as `attach` or drop `filename`. It ended as `upstream_unreachable` after four attempts; this publish is no longer retried. A blank `filename` or `attach` is sent as unset ([#46](https://github.com/cyanheads/ntfy-mcp-server/issues/46)).
- **A blank `delay` is sent as unset**; the result reported `scheduled: true` while ntfy delivered at once.
- **Body truncation could split a surrogate pair**, leaving a lone high surrogate that strict JSON parsers reject. The cut backs off to a code-point boundary, and `messageTruncated` counts dropped UTF-16 code units (an emoji counts 2) ([#48](https://github.com/cyanheads/ntfy-mcp-server/issues/48)).
- **ntfy's `icon` was dropped** from `ntfy_publish_message` output, fetched rows, and `ntfy://{topic}` rows. Each returns it as ntfy sent it and renders `Icon:` as a code span ([#49](https://github.com/cyanheads/ntfy-mcp-server/issues/49)).
- **A numeric `since` of 10¹² or more is rejected as `invalid_since` before any request**: a whole number from 1000000000000 up, such as a millisecond timestamp, with or without a leading `+` or zeros. ntfy read it as Unix seconds and returned an empty window ([#52](https://github.com/cyanheads/ntfy-mcp-server/issues/52)).
- **A numeric `since` below 10⁹ adds a notice naming the instant ntfy read it as** (`10` is `1970-01-01T00:00:10Z`) and that a duration needs a unit (#52).
- **An all-digit 12-character `since` adds a notice that ntfy read it as a message ID**, not a timestamp (#52).
- **A tag named exactly by the `ntfy_search_emoji_tags` query comes first**, the rest in reference order; 22 tag names (`x`, `ok`, `us`, and others) fell past the default 25-row page (#53).
- **An answer that did not come from an ntfy topic route fails as `not_ntfy_endpoint`** with a recovery hint, and its message names the host the request went to instead of `ntfy`. It covers an answer without ntfy's JSON error envelope on a 3xx, a 4xx other than 408, 425, and 429 (a 404, 405, or 401 or 403 among them), or a 501, and ntfy's own `40401`. Any other ntfy envelope, a 429, and every other 5xx keep their reasons. `ntfy_manage_message` keeps every 404 as `not_found`, and JSON-RPC codes are unchanged ([#55](https://github.com/cyanheads/ntfy-mcp-server/issues/55)).

## Security

- **Log records and the log notifications sent to clients no longer carry topic names.** Error data `topic` and the resource URI fields are redacted in every log sink, the failure messages that named the topic no longer do, and a response body captured from a host that is not ntfy has topic names masked. Callers still receive `data.topic` ([#54](https://github.com/cyanheads/ntfy-mcp-server/issues/54)).
- **Not covered:** the framework's `mcp.resource.uri` attribute on `resource_read:*` trace spans (cyanheads/mcp-ts-core#861); a topic name cut by the 500-byte body capture can leave a fragment; and an upstream that answers in ntfy's JSON envelope and names the topic in its error text has that text folded into the message as written.
