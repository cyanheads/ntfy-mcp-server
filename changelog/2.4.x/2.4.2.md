# 2.4.2 — 2026-11-17

## Added

- **`ntfy_fetch_messages` `wait_seconds` input and `waitedSeconds` output** ([#61](https://github.com/cyanheads/ntfy-mcp-server/issues/61)): when the poll matches nothing, the call holds ntfy's stream open for up to 40 s and returns the first matching message, skipping the message `since` names. Ten waits run per server process, a stream line over 1,048,576 characters ends a wait, and `NTFY_CLAMP_LIMITS` governs a larger value. Pass the arrived message's `id` as `since` to wait for the next one; a row that shares its `time` may have been published before it.
- **`quota` on `ntfy_publish_message` and `ntfy_manage_message` results** ([#60](https://github.com/cyanheads/ntfy-mcp-server/issues/60)): the daily `messages` and burst `requests` allowances ntfy reports on the response, each with its `limit`, `remaining`, and seconds until reset or the next request; absent when ntfy reports none.
- **`data.limit` on `rate_limited` errors** (#60): `requests`, `messages`, `emails`, `calls`, `bandwidth`, `subscriptions`, or `topics`, each with its own recovery hint, on all four surfaces; a 429 without ntfy's error envelope carries none.

## Fixed

- **The 400 sub-reasons and oversize hints are read from the `error` text of ntfy's own error envelope** ([#57](https://github.com/cyanheads/ntfy-mcp-server/issues/57)): `payload_too_large`, `invalid_delay`, `invalid_attachment`, `unverified_contact`, `invalid_since`. A 400 or 422 page or reason phrase from a host that is not ntfy fails as `not_ntfy_endpoint`.
- **`ntfy_publish_message` no longer caps `tags` at 10 or an action `label` at 64 characters** ([#59](https://github.com/cyanheads/ntfy-mcp-server/issues/59)); ntfy's 512-byte total for tags is the only tag bound, named in the `tags` description and its `payload_too_large` hint.
- **`ntfy_fetch_messages` describes `sequence_id` as set on any row whose publish carried one** and labels it `Sequence ID:` instead of `References sequence:` ([#62](https://github.com/cyanheads/ntfy-mcp-server/issues/62)).
- **A blank `click` or a blank tag is sent as unset**, as ntfy reads it.
- **A publish ntfy refuses for the size of the whole request** (its 41303) **gets a recovery hint about the request**, which must stay under 8,192 bytes on a default ntfy server, instead of the message-body hint.

## Security

- **A base URL never carries credentials** ([#58](https://github.com/cyanheads/ntfy-mcp-server/issues/58)): a `base_url` with `user:password@` is refused by all three tools with `data.baseUrlRejected` before any consent prompt or request, and credentials in `NTFY_BASE_URL` or an `NTFY_SERVERS` `baseUrl` fail startup naming the variable. `https://@host` is accepted as `https://host`; no rejection quotes the value.
- **The consent prompt for a publish with `email`, `call`, or a `broadcast` or `http` action lists one line per side effect** ([#63](https://github.com/cyanheads/ntfy-mcp-server/issues/63)): an `http` line names the button's label, method, URL, body, and header names (never values), a `broadcast` line its label, intent, and extras. Every caller-supplied value is one code span with control, line-separator, and bidi or other format characters shown as escapes. A destination (the `email` address, `call` number, `broadcast` intent, `http` URL) shows whole; any other value shows its first 200 characters and states its full length.
- **A failed request to ntfy reports no request URL.**
- **Base-URL normalization takes time linear in the URL's length.**
- **The startup message for an `NTFY_SERVERS` value that is not valid JSON quotes none of the value.**
