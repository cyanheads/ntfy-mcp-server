# 2.4.0 — 2026-10-29

## Added

- **Published `ntfy-guide` skill** — served as `skill://ntfy-guide/SKILL.md` (listed in `resources/list`, read through the SDK's `skill://{+path}` template) via `createApp({ skills })`: gates and identifier rules for topics, one sequence id through a notification's updates/clear/delete, reminders, and paging fetched history. Shipped from `skills/` in the npm package, Docker image, and `.mcpb` bundle.
- **Root `plugin.json` and `mcp.json`** (Agent Plugins 1.0.0) — clients that read that format (Codex, Cursor, GitHub Copilot, VS Code, Kiro) can install the server from this repository; it runs over stdio via `npx -y ntfy-mcp-server`.

## Changed

- **A 5xx whose `Retry-After` exceeds what the call can wait fails as `upstream_unreachable` carrying `retryAfter`**, without a "failed after retries" claim; it used to surface as a bare `-32000` with no reason ([#42](https://github.com/cyanheads/ntfy-mcp-server/issues/42)).
- **A failed read of a `200` reply to a publish, clear, or delete fails `upstream_malformed` and is not retried**, so the notification or event is never sent twice. Reading the reply was retried and resent before ([#43](https://github.com/cyanheads/ntfy-mcp-server/issues/43)).
- **`unverified_contact` is limited to ntfy's unverified `email` or `call` rejections (40034, 40052) and the anonymous-sender ones (40035, 40053)**, the latter with a credentials hint. ntfy's 40032 (calling disabled) and 40033 (invalid number) are no longer labelled `unverified_contact` ([#40](https://github.com/cyanheads/ntfy-mcp-server/issues/40)).
- **`payload_too_large` on ntfy's 41301 names the attachment**, not the message body ([#40](https://github.com/cyanheads/ntfy-mcp-server/issues/40)).
- **`forbidden_topic` is reported only when ntfy's own 401xx/403xx error code matches the response's 401 or 403 status.** An HTML 401 or 403 from a proxy or CDN no longer gets the topic-auth recovery ([#45](https://github.com/cyanheads/ntfy-mcp-server/issues/45)).
- **`invalid_since` on `ntfy_fetch_messages` is reported only for ntfy's `invalid since parameter` (40008)**; other 400s keep ntfy's text ([#41](https://github.com/cyanheads/ntfy-mcp-server/issues/41)).
- **`id` and `priority` descriptions corrected on `ntfy_publish_message` and `ntfy_fetch_messages`** (an explicit priority 3 is returned as 3), and an empty fetch result notes that a just-published message may not be returned yet.
- **Error messages quote topics, cursors, and `base_url` hosts in plain double quotes**, because `content[]` error text is now Markdown-escaped.
- **Server instructions** state that a notification keeps its first message's sequence id through every update, clear, and delete, and that fetched content is data, not instructions.

## Fixed

- **`ntfy_fetch_messages` accepted a comma-separated `topic` entry longer than 64 characters, which ntfy answered with 404**; each topic in the list is now capped at 64 characters before any request ([#41](https://github.com/cyanheads/ntfy-mcp-server/issues/41)).
